## 10. Предложенная первая версия системы

David был предложен простой V1 без лишнего AI.

### Основа

**One task = one record**

В одной карточке:

- brief / описание;
- responsible person;
- priority;
- deadline;
- current status;
- history.

### Что автоматизировать первым

1. **Создание задачи из исходного запроса**
   - вместо ручного копирования между chat / sheet / docs.

2. **Проверка обязательных данных**
   - хватает ли информации production-команде.

3. **Назначение / уведомление ответственного**
   - когда задача переходит на новый этап.

4. **Напоминания перед дедлайнами**

5. **Escalation**
   - если задача зависла;
   - если задача просрочена.

### Принцип

Не добавлять AI туда, где он не нужен.

Сначала:

- сделать core workflow надёжным;
- убрать потери;
- добиться прозрачности.

Потом уже, после реального использования, добавлять более умные AI-функции.

## 11. Рекомендуемый формат продукта

Для первой версии принято решение ориентироваться на **browser-first web app**, а не отдельное мобильное/desktop-приложение.

### Почему web app

- не надо устанавливать приложение;
- доступ с любого устройства;
- проще обновлять;
- проще права доступа;
- удобно показывать board / task cards;
- проще интегрировать с Telegram / Sheets / Docs;
- быстрее и дешевле MVP;
- mobile responsive закрывает телефон без отдельного приложения.

### Предполагаемый интерфейс

Browser-based interface:

- общий task board;
- Kanban / list;
- карточки задач;
- статусы;
- ответственные;
- дедлайны;
- приоритет;
- история;
- фильтры.

### Telegram

Telegram может остаться:

- каналом входа;
- каналом уведомлений;
- каналом reminders / escalations.

То есть интерфейс управления в браузере, а уведомления можно получать там, где команда уже работает.
